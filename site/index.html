A book is a folder you already understand.

Your manuscript folder holds one folder per chapter and one Markdown file per scene. Proseview reads that shape and builds everything else from it.

  1. BookThe manuscript folder: word count, goal and pace.
  2. ChaptersA folder each, in the order you name them.
  3. ScenesA Markdown file each, with optional notes on who, where and when.
my-novel/
└── manuscript/
    ├── ch01/
    │   ├── 01-the-letter.md
    │   └── 02-the-station.md
    └── ch02/
        └── 01-aftermath.md

Write

The page you read is the page you write on.

  • Press E and the typeset page becomes the editor. Cmd-S saves and takes you back to reading.
  • Story bibles, plans and any other Markdown file are editable too.
  • Search the whole book with Cmd-K, and choose from six themes and seven fonts.

Revise

An editor's eye, on your terms.

  • Nine prose passes marked on the page: repetition, filter verbs, passive voice, crutch words and more.
  • Chapter pacing, sentence rhythm and who appears where.

Plan

See every storyline at once.

  • Each storyline gets its own lane across the book, from a thread: line in a scene's frontmatter.
  • Chapter lengths and words per scene, to spot a chapter that runs long.

Ask, if you want to

Your own Codex or Claude, when you ask.

  • No new model, no API keys and no limits from Proseview. It uses the Codex or Claude you already sign in to, the way their VS Code extensions do.
  • Optional, and it never runs on its own.
  • An edit is saved with a small card that shows what changed, and Undo all puts it back.

Publish

From manuscript to the shelf.

  • An EPUB for every e-reader, and a paperback interior from 5 × 8 to 6 × 9 inches or A5.
  • A Word document for your editor's tracked changes, and standard manuscript format for agents.
  • A plain-language check that the book is ready for the stores. Nothing else to install.

Fits the way you already write.

Obsidian

Point Proseview at your vault and nothing moves. Wikilinks, callouts and embeds stay exactly as you wrote them.

Git, for backup

Your book is plain text, so git keeps every draft. Push it to a private GitHub repository and it is backed up off your computer. Each commit shows exactly what you changed, and your commits feed the writing streak and goal progress.

VS Code

Open any scene in VS Code, Cursor or Zed with one click and keep it open beside Proseview. A change saved in either one shows up in the other.

Questions

Is it really free?

Yes. Proseview is open source under the MIT licence, with no paid version, no subscription and no account. If you use the optional AI panel, Codex or Claude bill you under your own plan with them.

Where is my book stored?

On your computer, as plain Markdown files in your own folder. If you start a book in the browser, it is kept in that browser's storage on your device, and clearing the site's data deletes it, so use Download it to keep a copy. Proseview has no server that receives your book. To back it up, keep the folder in git and push it to a private repository, on GitHub or anywhere else.

Do I need Obsidian?

No. Any folder of Markdown files works, and Proseview can create the files for you. If you do use Obsidian, Proseview works on your vault without changing how it is written.

Do I need git?

No. Proseview works on any folder. Git is the easiest way to back the book up and keep every draft, and in a git folder Proseview also reads your commits for the writing streak, goal progress and recent changes.

Do I need AI?

No. Everything except the agent panel works without it, and the agent panel does nothing until you ask it something.

Can I move a book from the browser to my computer?

Yes. Download it gives you the book as a zip of its folder. Unzip it and run proseview --root on that folder.
