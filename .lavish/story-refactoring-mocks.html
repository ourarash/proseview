Proseview product concept · interactive mocks

AI-assisted story refactoring, with the writer still in control

A proposed extension of Discuss that traces a canon change through the repository, presents evidence, turns each affected passage into a reviewable proposal, and verifies the result.

How to review: switch among the four screens, click the mocked controls, and annotate any element or text in Lavish. The mocks favor an evidence-first workflow: scanning does not modify files, and every edit remains individually reviewable.

Start with intent, not a blank chat box

Three writer-centered actions make the feature discoverable while ordinary Discuss remains available.

Key choice: “Trace a canon change” first performs a read-only scan. It does not imply that every textual match should be rewritten.

Suggested delivery sequence

What I would actually build

The mocks show the complete direction, but the implementation can land in useful slices.

MVP · recommended

Evidence-first continuity actions

Add the three Discuss entry points and structured, cited findings.

  • Read-only repository scan
  • Direct / ambiguous / intentional grouping
  • Exact file and passage evidence
  • Open source and mark intentional
Next

Proposal handoff

Turn a finding into the existing single-passage proposal workflow.

  • One-click “Review proposed edit”
  • Existing stale checks and alternatives
  • Queue status in a lightweight rail
  • No batch write endpoint
Then

Persistent refactor sessions

Remember decisions and verify the repository after edits are saved.

  • Resolved / rejected / intentional states
  • Repeatable verification scan
  • Exportable evidence report
  • Resume after restart
